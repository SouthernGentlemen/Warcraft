# Incremental Systems

## Purpose

This section defines the time-based, offline, queue, and automation systems that make the game function as an incremental RPG.

## Incremental Philosophy

The player should make meaningful strategic decisions and then allow the game to execute those decisions over time.

As the roster and base grow, the game should reduce repetitive manual work rather than multiply it.

## Time-Based Activities

Systems likely to use time include:

- missions
- hero recovery
- crafting
- construction
- building upgrades
- recruitment
- training
- resource production

Exact timers are not yet defined.

## Mission Queues

Heroes assigned to content are expected to be unavailable for incompatible simultaneous deployments.

The game may allow multiple missions to run concurrently as the player develops the base.

## Offline Progress

Time-based systems should continue progressing while the player is offline.

Offline progression must be predictable and use the same underlying rules as online progression wherever practical.

## Automation

Higher progression may unlock automation for repetitive tasks such as:

- repeat missions
- crafting queues
- resource collection
- equipment management
- recruitment refreshes

Automation should be earned as organizational progression and should not remove important strategic choices.

## Concurrency

The game must eventually define how many activities can occur at once across:

- missions
- crafting
- construction
- training
- recruitment

Concurrency is likely to be an important base-upgrade reward.

## Open Areas

Later incremental design must define:

- timer ranges
- offline limits
- queue sizes
- concurrent missions
- automation unlocks
- repeat rules
- idle resource production
- catch-up mechanics
