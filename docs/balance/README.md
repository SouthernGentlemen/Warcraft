# Balance

## Purpose

This section will hold the numerical model that connects heroes, enemies, content, equipment, resources, crafting, and time.

The other design sections should define what systems do before this section fixes exact numbers.

## Balance Goals

The final model should create a clear sense of progression without making earlier content immediately worthless.

Balance should support:

- meaningful hero growth from Level 1 to Level 5
- increasing value from roster depth
- escalating party sizes
- useful equipment progression
- useful crafting at every tier
- understandable resource costs
- predictable incremental pacing
- multiple viable class compositions

## Major Curves

The balance model will eventually define:

- hero power
- enemy power
- experience requirements
- mission difficulty
- mission duration
- equipment power
- crafting costs
- building costs
- resource income
- resource storage
- drop rates
- reward quantities
- recovery time

## Tier Targets

Each tier should have explicit target ranges for:

- time to reach
- expected roster size
- expected hero levels
- expected equipment
- expected base state
- expected profession state
- available content
- resource income and spending

## Formula Ownership

When detailed design begins, each important formula should have one authoritative definition rather than being duplicated across documents.

## Open Areas

Almost all exact numbers remain intentionally undefined until the high-level game systems are reviewed.
